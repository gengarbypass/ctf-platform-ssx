# 赛题构建模板（动态容器 / 动态 Flag 出题指南）

**适用平台**：蓝域 CTF（ctf-platform-ssx）`897749d` 及以上
**读者**：出题人 / 靶场镜像构建者。平台不构建镜像，只按名称在 ECS 宿主 Docker 上创建容器——本文说明镜像需满足的契约、平台侧配置方法与端口/Flag 规则。

---

## 1. 四种出题形态

| 形态 | 镜像配在哪里 | Flag 配置 | 容器 | Flag 注入环境变量 |
|---|---|---|---|---|
| 解题赛 · 静态 | 不填 | 必填（固定答案） | 无 | — |
| **解题赛 · 动态** | 赛题的「环境镜像」 | **留空** | 每队每题一个 | `FLAG`（另附 `FLAG_<赛题ID>`） |
| **AWDP 靶机** | 靶机的「环境镜像」（题库） | **留空**（也可填静态答案） | 开赛后平台为每队自动开启，整场运行 | `FLAG`（另附 `FLAG_<靶机ID>`），可布置多个靶点共用该值 |
| 综合渗透 · 静态 | 比赛的「环境镜像」不填 | 必填 | 无 | — |
| **综合渗透 · 动态** | 比赛的「环境镜像」 | **留空**（批量创建） | 每队整场一个 | `FLAG_<靶点ID>` × 靶点数 |

动态模式下 Flag 不由出题人填写：平台为每支队伍的**环境**生成独立密钥，按
`flag{e<环境编号>-<16位hex>}` 派生每枚 Flag，注入容器后由选手取出提交，平台同式派生比对计分。
同一队重启环境：**Flag 保持不变**，但会分配全新的访问端口（端口台账保证永不与历史端口重复）；不同队伍的 Flag 互不相同。

---

## 2. 镜像契约（出题人必须遵守）

1. **读取注入的 Flag**，禁止硬编码：
   - 解题赛镜像：读环境变量 `FLAG`；
   - 综合渗透镜像：遍历所有 `FLAG_*` 环境变量（不必关心编号与层级的对应，层级由平台侧命名）。
2. **服务监听 `0.0.0.0`**，端口与平台配置的「容器端口」一致（默认 80，建议直接监听 80 免配置）。
3. **不依赖外网**：环境容器使用独立 bridge 网络，与平台及其他队伍隔离，仅暴露发布端口。
4. **可丢弃**：容器可能被重启、到期回收；持久化数据（数据库、上传文件）重启即失。需要"初始状态"的题在启动脚本里每次重新生成。
5. 资源上限（平台强制）：单容器 内存 768MB / CPU 1.5 核 / 进程数 320。超限会被 Docker 杀掉，请控制题目负载。
6. 基础场景建议：Web 类用 python:alpine / php:apache；复合靶场（多服务）在容器内用 supervisord 或启动脚本拉起。

## 3. 最小出题模板（解题赛 · Flask）

**app.py**

```python
import io
import os
from flask import Flask, send_file

app = Flask(__name__)
FLAG = os.environ.get("FLAG", "flag{placeholder-selftest}")

# 示例形态：flag 藏在"备份文件"里（按题目设计自行改造放毒位置）
@app.get("/")
def index():
    return "<h1>内部归档系统</h1><p>请下载 <a href='/backup.zip'>backup.zip</a></p>"

@app.get("/backup.zip")
def backup():
    return send_file(io.BytesIO(FLAG.encode()), mimetype="application/zip",
                     download_name="backup.zip")

@app.get("/flag.txt")          # 或直接做读文件类题
def flagfile():
    return FLAG + "\n"
```

**Dockerfile**

```dockerfile
FROM python:3.12-alpine
WORKDIR /app
COPY app.py .
RUN pip install --no-cache-dir flask -i https://pypi.tuna.tsinghua.edu.cn/simple
EXPOSE 80
CMD ["flask", "run", "--host=0.0.0.0", "--port=80"]
```

**自测（出题机本地）**

```bash
docker build -t demo-web:1.0 .
docker run --rm -e FLAG=flag{selftest123} -p 8080:80 demo-web:1.0
curl http://127.0.0.1:8080/flag.txt        # 应输出 flag{selftest123}
```

**综合渗透多 Flag 版**（整场一个容器，多环节各一枚）

```python
import os
flags = {k: v for k, v in os.environ.items() if k.startswith("FLAG_")}
open("/opt/range/boundary.flag", "w").write(flags.get("FLAG_1", "") + "\n")
open("/opt/range/intranet.flag",  "w").write(flags.get("FLAG_2", "") + "\n")
# ……按环节放到对应服务/主机路径；环境变量有则写、无则写占位，保证容器总能启动
```

自测：`docker run --rm -e FLAG_1=flag{a} -e FLAG_2=flag{b} demo-range:1.0 cat /opt/range/boundary.flag`

## 4. 把镜像送达 ECS

平台直接使用 **ECS 宿主 Docker 中已存在的镜像**（或可从仓库拉取的镜像）：

- **方式 A · 离线导入（推荐，匹配内网赛场）**
  出题机构建 → `docker save demo-web:1.0 -o demo-web.tar` → 上传 ECS → `sudo docker load -i demo-web.tar`
  （与你现有 `iotmanage-images.tar` 分发流程一致）
- **方式 B · 镜像仓库**
  推送到 ACR 个人版 / Docker Hub，ECS 可直接 pull。首次启动环境会自动 pull（较慢），建议部署后先在 ECS 手动 `sudo docker pull` 预热。

导入后确认：`sudo docker images | grep demo-web`。

## 5. 平台侧配置（管理端）

### 解题赛动态题

1. 比赛：创建/编辑「解题赛」→ 可选填 **环境时长（分钟）**（默认 120）与 **环境并发上限**（默认 20）。
2. 题目管理 → 创建赛题：
   - **环境镜像**：`demo-web:1.0`；**容器端口**：镜像内监听端口（默认 80）；
   - **Flag：留空**（留空 + 有镜像 = 动态；填了 Flag 则静态答案同样可解，两者共存）；
   - 分值、分类、附件照常。
3. 开赛后：选手在题目页点【启动环境】→ 题目页显示 `http://<主机>:<分配端口>`。

### 综合渗透动态靶场

1. 创建比赛 → 模式「综合渗透」→ **环境镜像**：`iotmanage-dmz:1.0`、**容器端口**：80、时长/上限同上。
2. 题目管理 → 创建靶点（批量多行）：层级 / 名称 / 分值，**Flag 全部留空**。
3. 开赛后：选手在 `/breach` 点【启动环境】→ 一台整场靶场容器，内含全部 `FLAG_*`。

## 6. 端口与网络规则

| 项 | 规则 |
|---|---|
| 容器端口 | 镜像内服务监听端口，出题人在表单「容器端口」填写（默认 80） |
| 宿主端口 | 平台自动从 **8400** 起顺序分配（`CTF_ENV_PORT_START` 可调），每个环境占用一个；**每次重启分配全新端口，永不复用历史端口** |
| 选手访问地址 | `http://<访问主机名>:<宿主端口>`；反向代理/域名部署时设 `CTF_ENV_HOST` 指定展示主机名 |
| 队伍隔离 | 每环境独立 bridge 网络（`ctfenv-c<赛>-t<队>-p<题>`），队伍间不可互访、与平台容器隔离 |
| 安全组 | 入方向放行端口段，如 **8400-8500/TCP**（按队伍数 × 题目数预留） |

> 容量参考：单环境峰值 ≈ 768MB 内存 + 1.5 核。8 队 × 1 环境约 6GB 内存，请按 ECS 规格与「环境并发上限」匹配。

## 7. 生命周期（平台自动处理）

- 启动：点击【启动环境】→ 分配端口、生成密钥、创建容器（独立网络 + 资源上限）。
- 重启：同队再次点击 → **端口与 Flag 不变**，容器重建（容器内改动丢失）。
- 回收：环境时长到期、或比赛结束/撤下 → 容器自动停止移除（惰性触发，选手访问靶场页/提交时执行）。
- 上限：运行中环境数达到「环境并发上限」后拒绝新启动。
- 删除：删除队伍/比赛时自动清理其全部容器。

## 8. 出题自测清单

- [ ] 本地 `docker run -e FLAG=flag{selftest}` 后能按题目路径取到 Flag，服务监听 0.0.0.0
- [ ] 镜像已在 ECS 宿主 `docker images` 可见（或仓库可拉取）
- [ ] 平台建测试赛 → 配镜像 → 赛题 Flag 留空 → 开赛
- [ ] 选手启动环境 → 题目页出现地址且能访问 → 提交容器内 Flag → 判定「正确」并计分
- [ ] 另一队伍无法用自己的 Flag 解此题；停止环境后动态 Flag 不再匹配
- [ ] 比赛撤下后 `sudo docker ps -a | grep ctfenv` 无残留容器

## 9. 常见问题

| 现象 | 原因 |
|---|---|
| 启动环境报「启动环境容器失败」 | 镜像不在宿主且仓库拉取失败；或 sock 权限（检查 `deploy.sh` 输出的 GID） |
| 地址打不开 | 安全组未放行 8400+ 端口段；或服务只监听 127.0.0.1 |
| 提交容器内 Flag 判「错误」 | 赛题填了固定 Flag（静态优先）；或环境已过期/停止 |
| 全员 Flag 相同 | 出题人在镜像里硬编码了 Flag，未读环境变量 |
| 容器起来但题目异常 | 依赖外网，或非持久化数据在重启后丢失 |
